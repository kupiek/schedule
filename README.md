# Расписание ИЭК — мобильное PWA для GitHub Pages

Статическое веб-приложение (HTML, CSS, JavaScript) без сборщика, сервера и сторонних библиотек.

## Возможности

- **Моё расписание:** по умолчанию преподаватель с индексом **59** (`КупряковЕИ`), с выделением сегодняшнего дня по времени Иркутска.
- **Обзор:** поиск по всем группам и преподавателям с просмотром их расписаний.
- **Кабинеты:** просмотр расписания конкретного кабинета и поиск известных кабинетов без запланированных занятий на выбранную пару.
- **Чётность недели:** переключение между чётной и нечётной неделей; при открытии учитывается значение `GetSettings` из момента синхронизации.
- **PWA:** установка на экран смартфона, сохранение оболочки и просмотр уже загруженного JSON без интернета.
- **Настройки:** выбор преподавателя для главного экрана (сохраняется в `localStorage`).

## Почему здесь используется GitHub Actions

GitHub Pages обслуживается по HTTPS. Исходный API `http://scheduleapi.iek.irk.ru` использует HTTP, а браузер запрещает `fetch` к такому адресу с защищённой страницы. Даже при доступном HTTPS дополнительно нужна разрешающая CORS-политика сервера API.

Поэтому workflow `.github/workflows/pages.yml` каждые **два часа** и при ручном запуске:

1. Загружает `Groups`, `GetTeachersDistinct`, `GetSettings`.
2. Загружает расписания всех найденных групп и преподавателей.
3. Сохраняет нормализованные данные в `data/schedule.json`.
4. Публикует приложение как GitHub Pages со снимком расписания.

Это не push-уведомления и не прямое подключение к API в браузере: расписание обновляется после выполнения workflow. GitHub может задерживать запланированные задания, а доступность API с GitHub runners зависит от сетевых ограничений исходного сервера.

## Развёртывание

1. Создайте новый репозиторий GitHub, например `iek-schedule`, с основной веткой `main`.
2. Загрузите **всё содержимое этой папки** в корень репозитория (включая скрытую папку `.github`).
3. Откройте **Settings → Actions → General → Workflow permissions** и включите **Read and write permissions**, если запись снимка в репозиторий не разрешена.
4. Откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
5. Во вкладке **Actions** запустите **Refresh schedule and deploy PWA → Run workflow** либо дождитесь запуска при push.
6. Ссылка появится в настройках **Pages** (для обычного репозитория: `https://<ваш-логин>.github.io/iek-schedule/`).
7. Откройте сайт в мобильном браузере и выберите «Установить приложение» или «Добавить на экран Домой».

**Важно:** в архиве лежит пустая заготовка `data/schedule.json`. Она нужна для первой публикации. Сначала GitHub Actions должен успешно подключиться к API колледжа и заполнить её; до этого сайт показывает сообщение «Ожидается первая загрузка расписания». Если подключение из GitHub Actions к российскому серверу окажется закрыто, понадобится доступный HTTPS-посредник или другой сервер для синхронизации.

> Запланированные workflow у GitHub обычно исполняются в репозиториях с включённым Actions. Для публичных репозиториев GitHub может отключить запланированные workflow после длительного отсутствия активности. При необходимости выполните `workflow_dispatch` вручную.

## Локальная проверка

```bash
python3 scripts/sync_schedule.py
python3 -m http.server 8000
```

Открыть `http://localhost:8000`. Service Worker и установка PWA доступны на `localhost` и HTTPS, но не на произвольном HTTP-хосте.

Тесты данных:

```bash
node --test tests/*.test.mjs
```

## Ограничения источника

- API выдаёт **регулярный недельный шаблон**, а не подтверждённое календарное расписание с разовыми заменами.
- Если запись содержит объект `edit`, UI показывает пометку, но не интерпретирует его как замену на конкретную дату.
- Если две аудитории указаны через `//`, поиск учитывает обе аудитории; соответствие подгруппам не подтверждено.
- Список кабинетов извлекается из расписаний, а не из полного реестра помещений. «Свободно» означает «нет известной пары в снимке» и не является разрешением на использование.
- Время начала и окончания пар API не предоставляет.
- Если часть ответов недоступна, синхронизация может сохранять предыдущие данные по ним и отмечает неполноту в интерфейсе.
- Индекс преподавателя является **позицией в актуальном массиве** `GetTeachersDistinct`; скрипт не использует внутренний `teachersId` как индекс.

## Структура

```text
index.html, styles.css, app.js   — интерфейс
data-model.mjs                   — фильтры и нормализация расписания
service-worker.js               — автономная оболочка и кэш данных
manifest.webmanifest            — настройки PWA
assets/                         — иконки
data/schedule.json              — публичный снимок расписания
scripts/sync_schedule.py        — синхронизация с API
.github/workflows/pages.yml     — публикация на GitHub Pages
tests/                           — тесты модели данных
```
